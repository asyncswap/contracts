Deployments

Async Swap is deployed on four testnets and has no mainnet deployment. The earlier deployments on Unichain and Arc mainnet were tests, had bugs, and are archived: do not send orders to them. Every contract in the table is source-verified on Sourcify (full match), and every hook is owned by 0x33ce69DA05c3ad30A3b525625F950fAda8673205.

How to read the table:

  • AsyncSwap, Router, FeeVault are the protocol. The hook address is mined per chain for its Uniswap v4 permission bits, so it differs by chain, and FeeVault is created by the hook's constructor. The Router is the same on every chain except Ethereum Sepolia.
  • AsyncMatching, TickPrice, DynamicFeeOrdering are linked libraries, created through the deterministic CREATE2 deployer (0x4e59b44847b379578588920cA78FbF26c0B4956C) with fixed salts, so they have the same address on every chain.
  • PoolManager is the Uniswap v4 singleton the hook is attached to; Async Swap does not deploy it.
  • Numeraire is the stablecoin every pool is priced in.
  • Hook start block is where an indexer should start reading the hook's events.

The per-chain registries in deployments/ are the source of truth: each deployments/<chainId>/<chainId>.json holds every address with its deployment transaction and start block. The docs site serves all of them, with each chain's name, explorer and numeraire, as one file at /deployments.json.

Deploying

script/deploy.sh <chain-key> [dry-run|broadcast|verify] deploys the libraries (when missing), the hook and the Router, then writes the registry. Each network has a wrapper: deploy-unichain-sepolia.sh, deploy-sepolia.sh, deploy-robinhood-testnet.sh and deploy-arc-testnet.sh. Chain addresses come from script/config/chains.json; RPCs and the keystore account come from .env.deploy (see .env.deploy.example).

With the keystore enrolled in Olive, Touch ID signs each step:

olive exec new-deployer -- script/deploy-arc-testnet.sh broadcast

On Ethereum Sepolia, put DEPLOY_GAS_MULTIPLIER=800 in front. verify submits every registry entry to Sourcify, then to the chain's Blockscout explorer when there is one, and writes standard JSON inputs to deployments/<chainId>/verify/ for manual upload.
