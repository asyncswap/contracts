Git Source

Title: AsyncFiller

Author: @msakiart

Stores open async orders and settles fills against them.

Authorization model: the maker authorizes a Router/executor at order-creation time (setExecutor[owner][executor] = true). All subsequent fill / cancel / updatePrice calls on the hook must come from that registered executor. The hook forwards its immediate caller (msg.sender) and the resolved end-actor address (filler / canceller) into this library; the executor is checked here, and PM settlement targets the actor.

fill

Full-fill. The caller (the hook contract) must be an authorized executor of the order owner; filler is the actual end-user paying the output and receiving the input. Must be invoked from inside an IPoolManager.unlock context.

Settle gross output (native only; ERC20 is pre-settled), pay the signed minimum less the trade fee to the maker, and mint fee claims to the vault. Burn input claims and pay the input less the trade fee to the filler. Both currency deltas net to zero. A failed fill reverts all legs.

beginFlashFill

Input-first half of a flash fill, run in the hook's context. Closes the order (so it cannot be repriced, cancelled, topped up, matched or filled again) and credits its escrowed input, less the trade fee, to filler as ERC-6909 claims. Returns the order's input and minimum output as they were.

The caller must then call settleClaimsOutput in the same unlock, after the hook has received the output as claims; otherwise the unlock cannot close and the whole fill reverts.

 
function beginFlashFill(
        State storage self,
        Book storage book,
        AsyncOrder memory order,
        bytes32 id,
        address executor,
        address filler
    ) internal returns (uint256 amountIn, uint256 amountOutMin);

struct OrderInfo {
        address owner;
        uint256 amountIn;
        uint256 amountOutMin;
        uint128 price;
        bool isBuy;
        bool zeroForOne;
        uint64 sequence;
        /// @dev Maker reprices so far; signed reprices commit to it (`OrderSignatures.hashUpdatePrice`).
        uint32 reprices;

        uint64 priorityFee;
        uint128 priorityKey;
        /// @dev Immutable settlement age; repricing only resets queue sequence.
