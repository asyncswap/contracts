AsyncMatching

Git Source

Linked matching module operating on the hook's order and radix-book storage.

Public library calls use DELEGATECALL, so ERC-6909 escrow remains owned by Async Swap.

_crosses

Decide whether a buy and a sell order cross, i.e. a price exists that satisfies both makers' limits.

Keys are the floor ticks of the exact limits, ordered by numeraire per asset, so two distinct prices can share a key. Strictly ordered keys decide the result directly, since a monotone key cannot invert a strict inequality. Equal keys are decided by a full-precision cross-multiply:

cross <=> buyIn/buyOut >= sellOut/sellIn <=> buyInsellIn >= sellOutbuyOut <=> floor(buyIn*sellIn / sellOut) >= buyOut (sellOut, buyOut are nonzero).

An exact tie counts as a cross. With equal keys the quotient is on the order of buyOut, so the mulDiv cannot overflow for escrowable amounts.

function _crosses(
        uint128 buyKey,
        uint128 sellKey,
        AsyncFiller.OrderInfo storage buy,
        AsyncFiller.OrderInfo storage sell
    ) internal view returns (bool);
