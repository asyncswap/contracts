DynamicFeeOrdering

Git Source

Title: Dynamic fee ordering on pool-liquidity fills

Linked library called by AsyncMatching in the hook's context.

Constants

ORDERING_WINDOW

Blocks a pool fill's starting tick stays the reference that later fills are measured against.

 
uint256 internal constant ORDERING_WINDOW = 2;

Functions

charge

Dynamic fee on a pool fill that backruns a price move, taken from its output. The first pool fill in a window of ORDERING_WINDOW blocks records its starting tick as the reference. A later fill in the window that moves the price back toward the reference pays half the price gap it closes: amountOut * avgGap / 2, with the gap averaged over the fill's start and end ticks (one tick is about 0.01%), so splitting a backrun does not lower its total. Half of the fee is donated to in-range LPs and half credited to the FeeVault as claims.

 
function charge(
        AsyncFiller.State storage self,
        PoolKey calldata key,
        bytes32 id,
        Currency output,
        int24 tickBefore,
        uint256 amountOut
    ) public returns (uint256 fee);

A pool fill paid the dynamic fee, in currency (the fill's output): toLps donated to in-range LPs and toFeeVault credited to the FeeVault, measured against refTick.

PoolPriceObserved

The pool tick before and after a completed pool fill, with the reference used for fee ordering.

Indexers can use these events as the price-movement log; fee calculation uses compact on-chain state.
