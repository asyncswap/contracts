Git Source

Inherits: EIP712, Multicall

Title: Router

Author: @msakiart

Thin entrypoint for makers (swap, cancelOrder, cancelAndWithdraw, withdrawClaims), fillers (fillOrder) and keepers (matchBook, fillFromPoolLiquidity), batched with multicall. Each action goes through IPoolManager.unlock so the hook can operate on PM debts. Native payouts/refunds are PoolManager claims (ID 0), redeemable through NativeClaims or withdrawClaims; ERC20 payouts remain direct.

Gasless variants (swapWithSig, cancelWithSig) take the maker's EIP-712 signature so a relayer can submit. Signed creates pull input through Permit2 with the order as witness, so the wallet shows the full order (tokens, amounts, pool) in one readable message.

multicall runs several of these as one atomic transaction, each as the caller (for example, cancel many orders and withdraw the claims). It is not payable, so native-value actions (swap with native input, fillOrder with native output) cannot reuse one msg.value. Each action keeps its own PoolManager unlock and sets the transient slots it reads.

Order creation and fills (swap, swapWithSig, fillOrder, fillFromPoolLiquidity) pay an MEV tax ("Priority Is All You Need", Robinson & White): mevTax(), the transaction's priority fee per gas times MEV_TAX_GAS, in ETH on top of any native deposit, credited to the FeeVault as native claims. On a chain that orders by priority fee, searchers racing for the same position bid it up, so most of what they race for goes to the protocol; a transaction with no priority pays nothing. Inside multicall, which is not payable, a taxed action needs a transaction with no priority.

swap

Maker submits a new async order. userData must encode AsyncSwap.UserParams with executor == address(this) so the router is authorized to fill later. userData.amountOutMin MUST equal order.amountOutMin — the router enforces this so the limit price the maker signs in order is exactly what beforeSwap stores via hookData.

The hook auto-assigns a salt on create and emits it in AsyncOrderCreated. Submitters can pass order.salt = bytes32(0) on initial submission; the field is only read on cancel / updatePrice / fill paths (where the maker supplies the salt fetched from the indexer or event log).

Native input (currency0 = address(0) and zeroForOne = true, OR currency1 = address(0) and zeroForOne = false) requires msg.value == order.amountIn — the router holds the ETH and settles it to PM during unlock. For ERC20 input the maker must approve the router for amountIn of the input token. Either way msg.value also carries the MEV tax (mevTax(), zero without a priority fee).

function swap(AsyncOrder calldata order, bytes memory userData) external payable;

fillOrder

Filler completes an open order, paying exactly the maker's live minimum. The maker receives it less the 0.02% trade fee, and the filler the input less 0.02%. For ERC20 output, approve the router for that amount. For native output, msg.value must equal the live minimum; a stale or excessive deposit reverts rather than stranding the difference. msg.value also carries the MEV tax (mevTax(), zero without a priority fee). Native output is currency1 for zeroForOne, otherwise currency0.

maxPrice caps the output the filler pays — it protects fillers from a maker who front-runs them with updatePrice to bump the order's stored price. Pass type(uint256).max to disable the check. order.amountIn is the least input the filler accepts: the fill reverts if the order's live input has dropped below it (e.g. after a partial match).

function fillOrder(AsyncOrder calldata order, uint256 maxPrice, bytes calldata) external payable;

swapWithSig

Relayer submits a maker's signed order. The maker signs a Permit2 PermitWitnessTransferFrom for amountIn of the input token with spender = Router and the AsyncOrder witness (see OrderSignatures), so one signature both approves the transfer and commits to the order. Input then lands in the hook escrow exactly as in swap. Requires a prior Permit2 approval of the input token; native input is not supported (use swap). The relayer pays the MEV tax for its transaction's priority in msg.value.

function swapWithSig(AsyncOrder calldata order, PermitData calldata permit, ExecutorGrant calldata grant)
        external
        payable;
